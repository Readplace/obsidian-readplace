# Contributing

Bug reports and pull requests are welcome. Open an issue first for a new feature, because the plugin's scope follows Readplace's API.

## Build, test and lint

Use Node 22.

| Task | Command |
|---|---|
| Install | `npm ci` |
| Build once, with a type check | `npm run build` |
| Rebuild on change | `npm run dev` |
| Type check | `npm run typecheck` |
| Lint | `npm run lint` |
| Test, with coverage | `npm test` |
| Test the desktop application | `npm run test:e2e` |

CI runs the build, the lint and the tests on every push and pull request. To try a build, copy `main.js` and `manifest.json` into `.obsidian/plugins/readplace/` in a test vault.

## Desktop automation

Install Obsidian and Google Chrome first. On macOS, the test uses `/Applications/Obsidian.app/Contents/MacOS/Obsidian`. Set `OBSIDIAN_EXECUTABLE` to the installed executable on another platform. The `obsidian://` URI scheme must be registered with the operating system. Close other Obsidian instances before running the suite so they cannot receive its test callbacks.

Run `npm run test:e2e`. It builds a plugin connected to a local HTTP fixture, creates a separate vault and application profile under `test-results`, and drives the installed application. It restores the production build when finished. Credentials in this suite are generated by the fixture, and no Readplace account is needed.

Fresh CI runners set `OBSIDIAN_PROFILE` to the application's normal profile directory so the system URI handler reaches the same instance on every platform. This override refuses an existing `obsidian.json`; do not point it at a personal profile.

Results are in `test-results/results.json`, with screenshots and `evidence.json` in each test's output directory. Failed runs also produce a Playwright trace. The workflow uploads only these evidence files, never the application profiles or vaults.

Run `READPLACE_BENCHMARK_ARTICLES=2000 npm run test:e2e` to add a scale check with 2,000 additional articles of 10–20 KB each. It verifies the exact Markdown written to every note and checks that a repeated sync downloads no Markdown. The test allows up to ten minutes and records elapsed time, request counts, and Markdown bytes in `evidence.json`. This uses real Obsidian with the controlled local HTTP fixture; it does not measure a live Readplace account or network performance. Live validation with about 2,000 saves remains a separate check. The scale check is off by default.

For live staging validation, build with `READPLACE_SERVER_ORIGIN=https://hkncrxpii6.execute-api.ap-southeast-2.amazonaws.com npm run build`. A plain `npm run build` targets production. The origin is compiled into the bundle and is not a reader setting.

## Conventions

- Dependencies are injected. Only the composition root touches the real Obsidian objects, so everything else runs against fakes.
- zod validates what comes over HTTP, and nothing that TypeScript already types.
- No `as`, except `as const` and a test fake bound to a fixed signature.
- Use named parameters where 2 consecutive parameters share a type.
- Use the plugin's own `assert` for invariants.
- No `node:*` imports, so the code stays able to run on mobile.
- No code comments.
- Coverage is 100%, and tests sit next to their module. The composition root is the only ignored file.
- A test fake for HTTP takes the actual status it simulates, and tests don't use `jest.mock`.
- Hrefs from the server are opaque. Follow them, and never build a URL by hand.

## Releases

Run `npm version <version>`, which updates `manifest.json` and `versions.json` and tags without a `v` prefix, then push the tag. The release workflow builds the plugin, attests `main.js` and `manifest.json`, and creates a draft GitHub release to review and publish.
